# Working with AI assistants on this project

This file is read automatically by AI coding assistants. It says how they should help on this repository.

## Policy

This is a learning project. The backend code and its tests are **hand-written by the developer**. AI is used for specs, reviews, explanations and the frontend, not to write the backend for them.

## What an assistant may do

- Review code and pull requests against `CONTRIBUTING.md`, and point out real problems even if nobody asked.
- Write and improve specs, requirements, architecture decision records and other documentation.
- Explain concepts and trade-offs, and say how a decision would come up in an interview.
- Give a design, class and method structure, signatures and hints for backend tasks.
- Give exact steps for setup work: installing tools, Gradle and Docker configuration, Git commands, CI configuration.
- Build the frontend client, which is AI-generated by design.

## What an assistant should not do

- Do not write the backend application code or its tests. If asked for a solution, first offer a hint, then a stronger hint. Give a full solution only if the developer asks for it after trying.
- Do not add tools, libraries or services before a requirement needs them. Push back on over-engineering.
- Do not change the plan or the architecture without the developer's agreement.
- Never read, print or commit secrets. `infra/.env` stays on the developer's machine and is git-ignored.

## How to help

- Start from the simplest working version, then improve it step by step.
- Be specific and honest. Do not praise weak work. Name the file, the problem and why it matters.
- Check work against the issue's acceptance criteria and the Definition of Done in `CONTRIBUTING.md`.
- Give commands for Windows PowerShell, since that is the developer's environment.

## Where things are

| What | Where |
|---|---|
| Team rules, commit and PR format, Definition of Done | `CONTRIBUTING.md` |
| Vision, scope, personas, user journeys | `docs/requirements.md` |
| Functional requirements, business rules, use cases | `docs/functional-requirements.md` |
| Architecture decision records | `docs/adr/` |
| Local database setup | `infra/` and the README |
| Dependency and plugin versions | `gradle/libs.versions.toml` |

## Commands

```
./gradlew build            # compile, test, check formatting
./gradlew spotlessApply    # fix formatting
docker compose -f infra/docker-compose.yml up -d    # start PostgreSQL (needs infra/.env)
```
